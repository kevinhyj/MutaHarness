# MutaHarness

从筛选、序列挖掘或从头设计中找到一个有用的分子后，研发还需要反复改造和测试，才能改善活性、稳定性或选择性。**Fitness预测帮助决定下一轮值得测试哪些突变；实验反馈再用于更新预测。** 这是定向进化与 lab-in-the-loop 中连接计算和实验的环节。

![从先导分子发现到fitness引导的优化](assets/fitness-guided-evolution.png)

*概念示意图。Fitness指具体实验关心的分子性能；本项目聚焦右侧的突变排序与反馈学习。*

Task Option 2：下面从研发岗位与任务出发，展示两项Codex Harness改进及实测对照，再讨论更广范围的LLM能力评估与后续研究。

我选择突变效应预测作为科学评估任务：既有真实实验结果可核验，也能检验模型如何使用证据、学习反馈。评估同时关注排序质量、固定预算下的候选命中率，以及同模型、同生成预算下的Harness收益。

## 1. 行业岗位：谁在做什么？

蛋白药物、酶和生物制造的研发，通常围绕 **设计 → 制备 → 测试 → 学习 → 再设计** 展开。蛋白工程科学家决定优化目标，计算团队推荐候选，实验团队测量效果，工程师保证数据和设备流程能接起来。小团队中，一人可能兼任多个职责。

以下岗位参考 [Cradle 的研发工作流](https://www.cradle.bio/)、[实验室与自动化介绍](https://www.cradle.bio/lab)及 [Novonesis 的研发岗位](https://www.novonesis.com/en/careers/areas-of-work/research-and-development)。**时间比例是典型工作周的估计，每个岗位合计100%，不是企业工时调查。** 每行给出一条代表性 query 和输入示例；带链接的AMFR/GFP材料来自本仓库实测，其他条目为典型岗位场景的输入示例。

这里的 WT 是未改造的参考蛋白；MSA 是把许多同源蛋白序列对齐后得到的“自然变化对照表”。

## 2. 选择的难题：预测突变效应，支持下一批实验选择

本项目选择计算岗位中的 **fitness预测与反馈更新**。它是分子定向进化的关键环节：先预测候选性能，挑选一批做实验，再从返回的测量中学习。零样本用于没有本项目实验反馈的冷启动；少样本用于 lab-in-the-loop 中的排序更新。用于蛋白药物时，可以分别服务结合、表达或稳定性等目标。

这项任务的价值在于节省有限的实验名额。难点在于：同一个突变对稳定性和结合能力可能有不同影响；多个突变的效果不一定能相加；少量反馈又允许多种看似合理、泛化不同的模型。大模型能解释这些机制，但直接写出一长串分数，难以保证编号、证据和数百个候选的排序始终一致。

| 场景 | 代表性 query | 本仓库的实际 input | 输出 |
|---|---|---|---|
| 零样本冷启动 | 没有目标实验标签，根据结构和进化证据给这250个突变排序。 | [AMFR输入包](examples/zero_shot/amfr/)：参考序列、候选、结构与MSA证据，无已测反馈 | 每个候选的排序分数、所用证据与预测程序 |
| 少样本反馈学习 | 根据96条已测结果，为剩余186个GFP候选预测荧光排序，交付可执行程序。 | [GFP case.json](inputs/gfp_s2501.json)：序列、实验目标、96条反馈、186个未测候选 | 三份可复核的科研程序、融合排序和程序分歧 |

**两项已验证的改进：** 结构＋MSA让零样本平均Spearman从0.5051提高到**0.5736**；科研程序集成在同预算下从0.5843提高到**0.6093**。以下先展示方法与原生Codex对照，再展开领域能力评估。[运行示例](docs/getting-started.md) · [GFP完整案例](docs/case-study-gfp.md)

## 3. MutaHarness：两项 Harness 改进

Codex 已有通用的任务执行 Harness。MutaHarness 在其科学会话流程上增加结构/MSA证据分析、科研程序检查与排名融合，让它更适合突变效应预测。底层模型保持不变，模型仍可自由选择科学建模方法。

![两项Harness：科研程序集成与结构进化证据分析](assets/harness-workflows.svg)

左侧用同一份实验反馈生成三个科研程序，再检查并融合排名；右侧先将结构和MSA转成可用证据，再由Codex按实验目标组织预测。两条流程分别实测。

**Scientific Program Ensemble：集成模型写出的科研程序。** 将同一份反馈交给三个独立会话，各自提出假设、验证并交付可执行预测程序。程序可以采用不同特征、模型和变换。检查输出后，把三份分数转成排名，再等权融合。这样能利用不同科学方案的互补性，降低一次建模选择的影响。

**Structure + MSA：补充证据，并改善分析工具。** 结构提供突变位置的空间环境，MSA提供自然同源序列中的变化信息。工具先核对序列与残基编号，再计算接触、暴露、位点频率等证据，明确返回缺失与置信度。模型据此为具体实验目标组织预测，而不必仅凭序列文字猜测。

[方法、流程图与具体代码示例](docs/method.md) · [程序集成 Skill](.agents/skills/scientific-program-ensemble/SKILL.md) · [结构＋MSA Skill](.agents/skills/structure-msa-fitness/SKILL.md) · [MSA工具](tools/msa_tools.py) · [结构工具](tools/structure_tools.py)

**下载后即可运行两个示例。** 在仓库根目录使用Python 3.11+，无需API key或额外依赖：

```bash
python3 harness.py ensemble --out outputs/gfp_ensemble
python3 harness.py evidence --out outputs/amfr_evidence
```

第一条将已有三份GFP预测融合成186个候选的排名与分歧；第二条为250个AMFR候选生成结构/MSA证据。两者都校验输入，并输出含来源哈希的`manifest.json`。换成自己的数据时传入`--case`，融合入口另传三份`--predictions`。[输入格式、输出与使用说明](docs/getting-started.md)

## 4. 已有实测：相对原生 Codex，有多大收益？

以下均为此前已完成实验的存档结果。测试模型为 `gpt-6.1-sol / high`，Fast关闭。对照是原生 Codex，可使用工具并编写预测程序。以下使用相同的Spearman排序指标。

| 实验 | 对照 | 改进后 | 平均提升 | 提升任务数 |
|---|---:|---:|---:|---:|
| 零样本：基础 → Structure + MSA | 0.5051 | **0.5736** | **+0.0685** | **7/10** |
| 少样本：单次Codex → 三程序集成 | 0.5872 | **0.6093** | **+0.0221** | **8/10** |
| 少样本：同预算CV选单程序 → 三程序集成 | 0.5843 | **0.6093** | **+0.0250** | **8/10** |

**结构与进化证据改善了冷启动排序；程序集成在相同生成预算下，也优于从三个程序中只选一个。** 后一个对照用已测反馈的交叉验证（CV）选程序，能帮助区分“多生成几次”和“融合排名”的收益。

### 一个完整案例：用96条反馈预测GFP荧光

**Query：** 根据已测反馈，为186个未测GFP变体预测荧光排序，交付可重复执行的程序。输入是[238 aa参考序列、96条反馈与186候选](inputs/gfp_s2501.json)。

原生Codex独立建模并交付一个程序，Spearman为**0.5303**。MutaHarness把同一任务交给三个独立会话，分别得到核回归与非线性响应、树模型与非线性响应、树模型与位点反馈校正三个科学方案。三份程序通过执行检查后，排名等权融合得到**0.5819**。

同预算对照从这三份程序中，用已测反馈的CV选择程序B，结果为**0.5433**；融合比这一选择提高**0.0386**。[完整案例](docs/case-study-gfp.md)将原始任务、程序、实际排序变化和评估结果集中展示。

## 5. LLM能力评估：能预测突变，也能从实验反馈中学习吗？

前面的对照检验Codex的Harness收益。这里补充更广范围的领域比较，评估通用LLM本身的突变效应预测能力：根据实验目标、序列和可用的进化／结构证据给出预测，不进行任务专属微调。多轮实验中，已测结果直接作为上下文提供给LLM；领域模型则用表征＋随机森林（RF）学习反馈。这里的LLM能力包含给定证据和提示下的表现。

### 零样本：与领域预测方法比较

每个数据集（assay）对应一项实验读出，测试250个候选，不提供目标实验反馈。Spearman衡量预测排序与实验排序的一致程度，越高越好。

## 6. 观察与反思

已有结果让我更关心：**模型在什么条件下会出错，这些条件能否转成可验证、可扩展的评估题目？** 我会从具体表现提出能力假设，再用受控任务检验它。

| 已观察到的现象 | 想检验的问题 | 针对性的出题方式 |
|---|---|---|
| KRAS的结构＋MSA联合条件，在丰度与结合任务均下降 | 模型能否区分进化兼容性、稳定性与实验读出，并按目标使用证据？ | 从有配套测量的数据中取同一蛋白的重合突变，分别要求预测丰度与结合；固定候选和证据，比较各目标的排序 |
| GFP的反馈CV选B，测试时C最高，融合优于选出的B | 有限反馈下，怎样选择已有科学方案？ | 固定三个方案，改变反馈数量与组成；同预算比较选单程序与融合，测试结果由评估器保管 |
| 零样本Spearman提高，Top-25重合率未同步提高 | 模型能否根据实际实验预算调整决策目标？ | 同一候选池分别要求完整排序和限额选样；分别评价Spearman、命中率与累计发现 |

[逐任务结果](docs/results.md) · [GFP程序选择与指标](docs/case-study-gfp.md)。表中的问题是下一步要检验的假设，出题时还会配套容易条件与困难条件，观察性能随难度的变化。

**一个值得扩展的题型：从反例反馈中更新策略。** 从已有完整测量的assay构造任务：先给32条单点反馈，待选池以多点组合为主；允许追加查询8条真实测量，最后从剩余未测候选中提交10个。选择含真实反例的反馈条件，检查模型是否重新检验自己的规则、修改预测程序并调整后续查询。

评估同时记录工具调用、程序版本、排序变化和预算使用，最终按留出测量评价提交效果。对照包括原生Codex、无新增反馈策略及改进Harness，用来定位证据处理、科学泛化和策略选择的差异。

**扩大数据规模时，扩展的是任务条件与真实执行轨迹。** 同一实验可以改变目标、反馈数量与分布、突变阶数、证据可用性和预算。测量值保留原样，每轮只释放当时获得的反馈；轨迹由模型实际执行产生。实验多样性按assay与家族计数，任务覆盖度按配置计数，开发与测试按家族或研究划分。

这样得到的任务既能比较模型与Harness，也能为下面的预测训练、反馈学习和轨迹收集提供具体材料。

## 7. 未来方向：训练模型、学习反馈、积累轨迹

基于这些观察与评估设计，下一步重点放在：

1. **用synthetic data训练预测能力。** 从已测训练数据构造突变比较、组合效应、证据分析和逐轮反馈任务。标签与证据可核验，代理评分标明来源和置信度；按蛋白家族与实验任务隔离训练和测试。
2. **让Harness更好地从实验室反馈中学习。** 优化反馈组织、上下文更新、程序选择与集成，并在固定实验预算下评估候选命中率和累计发现，同时关注当前排序相关性与Top-K收益未同步的问题。
3. **让Harness收集可训练的设计trajectory。** 在用户授权下记录目标、工具调用与返回、候选选择、人工修改和实验反馈，保留每一步当时可见的信息。真实使用过程可以为模型和工具决策策略提供新的训练数据。

```mermaid
flowchart LR
  A[设计与工具调用轨迹] --> C[可验证训练数据]
  B[实验反馈] --> C
  C --> D[训练LLM与决策策略]
  D --> E[改进Harness]
  E --> F[下一轮候选选择]
  F --> A
  F --> B
```

这三点是后续研究设计，当前仓库交付的是已有实验、可复用流程与离线结果查看。[训练数据与轨迹设计细节](docs/llm-evaluation.md#未来研究设计)

## 8. 代码、交付与复核

工程代码从下面几处读起。排名融合、结果整理和页面交互各自独立，存档核对与页面数据生成只需 Python 3.11+，无需安装科学计算依赖。

| 入口 | 职责 |
|---|---|
| [harness.py](harness.py) | 两个Skill的统一命令入口；示例默认可跑，也接受自己的数据 |
| [runtime/workflows.py](runtime/workflows.py) | 输入校验、证据分析/预测融合、来源记录与结果输出 |
| [runtime/ranking.py](runtime/ranking.py) | 候选ID与分数检查、并列排名、等权融合、程序分歧；纯标准库 |
| [demo.py](demo.py) | 可选冷重放：校验哈希、分工作区执行、核对原预测、输出排序 |
| [scripts/results.py](scripts/results.py) | 报告、页面和图表共用的存档读取与指标整理 |
| [scripts/build_viewer.py](scripts/build_viewer.py) | 由数据与 [Markdown模板](docs/results.template.md) 生成结果页和报告 |
| [demo/viewer.js](demo/viewer.js) | 原生JavaScript交互；结构、样式和逻辑分文件维护 |
| [排名测试](tests/test_ranking.py)与[流程测试](tests/test_workflows.py) | 排名性质、命令端到端运行、来源哈希、错误输入与输出保护 |

`programs/` 是实测时模型生成的原始科研程序，`tools/` 和 `evidence/` 保留原工具与证据，便于追溯；工程入口的重构没有修改这些存档。

- **交互查看**：下载[仓库ZIP](https://github.com/kevinhyj/MutaHarness/archive/refs/heads/main.zip)，解压后双击 `demo/index.html`。可切换实验和任务、查看分数与已有候选排名；GitHub文件页显示HTML源码。
- **实测证据**：[程序集成](evidence/scientific_program_ensemble/)、[零样本首批](evidence/protein_zero_native01/)、[零样本追加批](evidence/protein_zero_native02/)，包含调用、程序、逐条预测和汇总。
- **复核存档**：`python3 -m scripts.audit_existing` 检查哈希、指标算术和页面数据，不调用模型或执行预测程序。[材料来源与打包范围](docs/provenance.md)

[LLM评估存档核对脚本](scripts/audit_evagent.py)另行检查五张图的来源与指标。本地检查与GitHub CI还使用以下命令：

```bash
python3 -m unittest discover -s tests -v
python3 -m scripts.audit_existing
python3 -m scripts.build_viewer
```

可选的程序重放：从96条反馈重新拟合冻结程序，核对输出与原记录。它不请求新模型，也不读取测试标签。

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python demo.py --case gfp_s2501 --out outputs/gfp_replay
```
